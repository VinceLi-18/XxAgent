# Agent Note: XAgent real CPU retrieval acceptance

Status: implemented

English | [中文](2026-09-04-xagent-real-retrieval-acceptance.zh.md)

## Problem

XAgent retrieval depends on PostgreSQL extensions, object storage, malware scanning, asynchronous artifact and index workers, a fixed tokenizer, and CPU embedding inference. Unit tests can validate each component while missing service-ordering defects, database-role drift, model-cache failures, stale lease publication, or differences between synthetic vectors and the deployed BGE-M3 model. A required end-to-end lane must exercise the assembled path without giving CI a public embedding endpoint, unbounded model downloads, or leftover Docker resources.

## Decision

The API Compose files define one private CPU retrieval topology. PostgreSQL 16 uses the pgvector image pinned by digest. The embedding Dockerfile pins `python:3.11-slim` to `sha256:9c900dea9e8fb7e16277c179b555cc72d29a352dbc33cff48ad5a0412fd5bfc7` and `ghcr.io/astral-sh/uv:0.8.15` to `sha256:a5727064a0de127bdb7c9d3c1383f3a9ac307d9f2d8a391edc7896c54289ced0`; the CI workflow spec fixes both source names and digests, and an embedding image build resolves them before acceptance. The service publishes no host port, limits CPU and memory, and is healthy only after immutable `BAAI/bge-m3` revision `5617a9f61b028005a4858fdac845db406aefb181` produces a 1024-dimensional vector. API and worker depend on that health result and use its service-network origin. Only the worker receives the worker database role.

Embedding UID/GID `65532:65532` owns the shared Hugging Face cache with owner write and read-only group/other access; API and worker mount the same cache read-only because both load the pinned tokenizer. The committed `bge-m3-snapshot.json` records the official immutable Hugging Face metadata endpoint and the exact snapshot file set with each file's size, SHA-256, and blob ID. A standalone verifier rejects malformed metadata, missing or partial snapshots, broken snapshot links, content drift, and any unmanifested non-directory entry inside the exact revision snapshot, including alternate weights, indexes, adapters, and symlink aliases. It does not traverse directory symlinks or confuse Hugging Face cache metadata outside that snapshot with model content. CI runs an absent-or-complete preflight before model loading, strict verification before tests and cache save, and keys cache entries by the model revision, embedding lockfile, and manifest. Online retrieval from the official source remains the default for an absent cache; only a strictly verified complete cache may set `HF_HUB_OFFLINE=true`. Docker and Python package inputs exclude the local cache.

The required pull-request lane runs the real upload, scan, index, search, receipt, Session evidence, citation authorization, and citation resolution path. Its retrieval fixtures make each ranking branch observable: the dense candidate has zero lexical score, the English lexical candidate falls outside the dense top forty, and the Chinese candidate has zero full-text rank, positive trigram score, and also falls outside the dense top forty. One equal-score pair makes VersionID, ordinal, and chunk-ID orders oppose ArtifactID order; another pair shares an Artifact and Version while chunk-ID order opposes ordinal order. These live assertions reach every live-reachable tuple level and fail if VersionID, ordinal, or branch-local chunk identity replaces ArtifactID precedence. `artifact_search_heads.artifact_id` is the primary key, so a valid live search cannot contain different searchable Versions for one Artifact; the direct fusion unit retains the VersionID fallback for that function's broader candidate-list contract without corrupting the database. Version replacement keeps the current generation searchable until the next ready index switches the head atomically. Invalid UTF-8 is MIME-classified and enqueued, then reaches exact terminal `failed:invalid-utf8` index and dead-job states without a head or retrieval result. Unsupported and quarantined inputs create no index; superseded and stale work cannot publish a searchable head.

Overlapping-worker recovery uses observable leases instead of delay-based coordination. The test keeps the first generation searchable, pauses the real embedding dependency while a one-off worker owns the replacement lease, then pauses that owner without killing it. A primary worker publishes a newer generation and reclaims the expired replacement job; the older owner subsequently resumes and completes its real process path. The assertions require the first head during rebuild, the newest head after publication, no superseded head, and no stale-owner publication. Every polling loop, HTTP operation, Compose command, service health check, and CI job has an explicit bound.

The CI step installs an unconditional exit trap before startup. Failure diagnostics run before teardown, the named one-off worker is removed, and Compose removes volumes and orphans. Exact worker-name and Compose project-label queries require container, volume, and network results to be empty, so a successful test command cannot conceal cleanup failure.

The [RAG retrieval proposal](../../proposed/architecture/2026-08-28-xagent-rag-retrieval.md) continues to own the runtime data, authorization, receipt, and citation design. This note owns the assembled deployment and acceptance strategy and does not supersede that proposal.

## Alternatives considered

**Mock the embedding service or seed arbitrary vectors.** This would not prove model loading, tokenizer compatibility, output dimension, real inference, or API and worker network wiring. The lane calls the running pinned model; direct database setup is limited to cardinality and ordering cases and still uses its real query vector.

**Publish the embedding port for host-driven tests.** This would make a private implementation service reachable outside the Compose network and certify a topology different from deployment. Tests invoke embedding from a Compose container when they need its vector directly.

**Use mutable image tags or trust a revision-only model cache.** Tags can resolve to different base layers, and a named model revision does not prove that every cached runtime file is complete or authentic. Exact image digests plus the committed per-file model manifest keep both inputs reviewable and fail closed before acceptance.

**Make the shared cache world-writable.** This lets unrelated runner users replace model or tokenizer data. Owner-scoped write permission gives the only writer, embedding UID 65532, the access it needs while API and worker remain read-only consumers.

**Bake model weights into a mutable local image.** This would create another large artifact and provenance lifecycle. A revision-and-manifest-keyed cache preserves normal official-source behavior and permits offline use only after content verification.

**Kill the only worker owner to test lease expiry.** That proves reclaim after a crash but cannot exercise late completion by the stale owner. Pausing one real owner while a second worker publishes a newer generation preserves both concurrent paths and tests fencing when the old owner resumes.

## Consequences

Pull requests gain a bounded, non-mock signal for the full XAgent retrieval stack, including overlapping generation ownership, immutable input verification, and exact cleanup. The lane is intentionally Linux-only and costly enough to remain separate from the ordinary API unit job. A cold GitHub-hosted cache downloads the immutable revision from the official source, so availability and bandwidth can affect that run; this path remains external evidence until the workflow executes on a pull request. Local acceptance proves the strictly verified warm-cache path and fail-closed corrupt, partial, and absent-cache behavior, but does not stand in for a hosted cold-cache run. Subsequent hosted runs reuse the revision-lock-manifest cache key. Any change to the model revision, manifest, tokenizer use, source-image digests, service dependencies, database roles, lease behavior, one-off worker name, or Compose project name must update this lane and its cleanup assertions together.
