# Agent Note: XAgent retrieval indexes, receipts, and least-privilege database roles

Status: implemented

English | [中文](2026-08-28-xagent-rag-retrieval.zh.md)

## Problem

Artifact retrieval must preserve immutable-version text chunks, 1024-dimensional vectors, keyword indexes, index jobs, the current searchable generation, short-lived receipts tied to Session evidence, and one-use delegation nonce digests. Keeping that state in the Host, Browser, or an in-memory job queue would duplicate FastAPI's Principal, project-membership, and Artifact Version authorization and would leave results without verifiable provenance after a process restart or permission revocation.

The index worker must write chunks and switch the search head, but it does not need account, authentication, Session, or project-membership data. The application role must read visible chunks and issue or consume receipts for the current actor, but it must not write embeddings directly. Without separate privileges and RLS, compromise of either runtime credential would expose unrelated users' Artifacts or identity data.

## Decision

PostgreSQL enables the `vector` and `pg_trgm` extensions and stores `artifact_text_indexes`, `artifact_text_chunks`, `artifact_index_jobs`, `artifact_search_heads`, `xagent_retrieval_receipts`, `xagent_admitted_evidence`, and `xagent_cited_answer_evidence`. An Artifact has one Index per generation, and a Version plus configuration fingerprint has at most one concurrent `building` Index. An Index can move only from `building` to `ready` or `failed`. Chunks are unique by Index ordinal, contain at most 8 KiB of text and 1–512 tokens, use a fixed `vector(1024)`, and have database-generated `simple` full-text and normalized trigram values.

Each Artifact has at most one search head, which can reference only a `ready` Index for the same Artifact and a Version that remains `clean`. A failed or unpublished new generation does not replace the existing head. Historical Indexes and chunks remain available to persisted citations.

A retrieval receipt binds the actor, Session, tool call, query digest, canonical scope, permission revision, returned projects, Indexes and chunks, and model-visible payload digest. A receipt expires exactly five minutes after issuance; an optional citation ordinal range contains only positive integers. `xagent_sessions.next_citation_ordinal` begins at 1 and increases monotonically, so ordinals reserved by expired or unconsumed receipts are never reused.

The Host fixes an authenticated request scope to every message entering the Agent inbox and activates it when the message is claimed. Queued input, steering, account changes, connection closure, and permission-revision changes cannot inherit another message's token. The two retrieval tools appear only in the Native tool path; Code SDK and nested Code dispatch do not expose them. The Host composition must provide an exact query counter for the pinned BGE tokenizer and fails closed when it is absent or returns an invalid count. The Host rejects malformed UTF-16, bounds query UTF-8 at 8 KiB and the worst-case escaped JSON body before sending, combines caller cancellation with a fixed timeout, rejects redirects, and accepts a count only after strict response type, size, UTF-8, field, model, and revision validation. It calls a fixed FastAPI relay with the existing backend origin and service token. The relay accepts neither user nor delegation tokens, bounds the body before parsing, and forwards only valid requests to the embedding endpoint on the service network. The internal endpoint loads only tokenizer assets for the pinned revision, isolates tokenizer concurrency from embedding inference, and waits for bounded cancelled tokenization threads before releasing their owner. Before returning a retrieval value, the Host registers its opaque receipt. Only publication of the corresponding `tool/result` permits binding to that Session Event; cancellation, blocking, and disposal must confirm non-publication or wait for a published result to finish binding. Receipts never enter model results, metadata, or logs.

Session Persistence obtains bound receipts by the first and last sequence of each append batch and submits them only in a private sidecar. An empty-queue flush returns before establishing an owner and cannot overwrite a write task created by an event that arrives synchronously. FastAPI first locks the Session, then a database finalizer serializes the current permission revision and rechecks the Session, existing project references, and the union of receipt projects. It next validates closed events, tool calls, the public payload digest, returned identities, and preallocated citation ordinals. A runtime `tool/result` must carry `surfaceOp: append`; optional `sourceEventSeqs` may refer only to unique events with smaller sequences in the same Session. A checkpoint may persist a `tool/call` before a later append persists its `tool/result`. The canonical public event preserves that provenance. FastAPI constructs closed public evidence events from validated results and writes redacted evidence audit, private-Session project references, receipt consumption, Session version, and the idempotency result in the same transaction. Append neither allocates nor rewrites citation ordinals; project discovery allocates none, and gaps from expired or unconsumed searches remain unused. The Host removes a receipt from the registry only when a closed successful backend response carries the exact final event sequence and a valid Session version. A failed batch retains the same events and sidecar for an isolated retry that must finish at the checkpoint before the next model request. The sidecar does not enter events, read responses, logs, or audit.

Receipt admission writes every server-canonical citation ID and its exact Artifact, Version, Index generation, Chunk, and physical event sequence to `xagent_admitted_evidence`. When the same append path accepts a canonical `xagent-cited-answer`, FastAPI binds each first-use citation ID to an earlier row and writes the answer relation to `xagent_cited_answer_evidence`; a composite foreign key requires every immutable identity and both event sequences to agree. An append without a cited answer performs no provenance or history query. A cited-answer append reads only its distinct citation IDs through the admitted-evidence primary key with an explicit row limit, so validation work is independent of Session history length. These relations are independent of `deriveMessages()` and of the admitting actor's receipt, so surface replacement cannot remove provenance and another currently authorized Project member can reopen the result. Citation resolution accepts only the Session and short citation ID, reads the answer relation through Session RLS, and reauthorizes the exact immutable Artifact Version and Chunk through current-actor RLS and the permission finalizer. Revocation therefore fails closed. A server-owned fork transaction copies admitted evidence inside the event cut, then cited-answer relations whose admission and answer are both inside that prefix, along with the source visibility, project, private project references, and exact events.

The Host registers Native-only `submit_cited_answer` only when the current model request contains non-empty evidence that matches checkpointed retrieval results in the Session. The model submits a final answer as a closed union of Markdown and citation blocks. Within fixed limits of 64 KiB JSON, 256 blocks, and 64 citations, the Host validates and canonicalizes the value and reconstructs authorization identities only from citation blocks. Markdown, raw HTML, character entities, and Unicode text grant no citation authority. The tool uses the current request token, permission revision, and a fresh delegation nonce for FastAPI reauthorization, then persists the canonical `tool/result`, projects replayable metadata, and ends the turn. Ordinary conversations and empty searches retain the normal streaming path.

One protected request accepts at most two final-answer submissions. The first schema, scope, citation-set, or reauthorization failure returns only a bounded tool error to the model and does not publish candidate text. A second failure, or completion without a successful terminal result, ends with a durable Chinese `CITATION_FAILED` turn error. Each protected request registers an independent owner after the evidence checkpoint. Every submission is staged by its exact ToolExecution; request, connection, Session, and service cancellation close admission and await authorization, result projection, and authoritative result observation. The Browser renders a rejected Tool result as the neutral “引用验证未通过，回答未发布” state without exposing arguments or content, while `CITATION_FAILED` remains the conversation's terminal failure. It renders only structured citation blocks as verified-Artifact chips; lookalike text does not enter the source strip or gain click capability. Selecting a chip opens the workbench's Artifacts tab and, after reauthorization, reads the exact clean immutable version and line range. The [structured cited-answer design](../../../../docs/superpowers/specs/2026-09-01-xagent-structured-citation-output-design.md) defines the complete protocol.

Before any retrieval work, FastAPI validates the Host's Ed25519 delegation token and persists the nonce's SHA-256 digest as a globally unique key. The raw token, raw nonce, and signature never enter the database or logs. The token strictly binds actor, Session, the Project Session's project or a Private Session's null project, endpoint tool, tool call, permission revision, and an expiry no longer than sixty seconds. Nonce consumption commits independently, so a later query failure cannot make the delegation reusable.

One serializable authorization snapshot covers login validity, permission revision, authorization for every project, vector and lexical candidate queries, citation-ordinal reservation, the receipt, and audit. Introspection inside this transaction fully validates the token, account state, login revocation, role, and revision but neither locks the authentication record nor updates its last-verification time; ordinary authentication paths retain that audit write. Read-only project authorization uses a SECURITY DEFINER function to reserve at most eight contiguous ordinals without granting the application role general Session update privileges. The model-visible citation payload counts complete JSON framing, identifiers, metadata, scope, and body with the tokenizer for the pinned embedding revision. It stops at the first 32 KiB or 4096-token overflow and preserves the RRF prefix.

Retrieval audit retains only Session and tool-call identities, scope and query digests, counts, result, latency, and at most eight sets of Artifact, Version, Index, generation, and Chunk identities. Database constraints validate fixed JSON fields and sizes. Queries, bodies, vectors, prompts, answers, URLs, receipts, signatures, and object keys must not enter audit.

The application role reads Indexes, chunks, heads, admitted evidence, and cited-answer relations through existing Artifact and Session RLS relationships. It may read, write, and update only the current actor's receipts, and may insert either evidence relation only for a Session the actor can edit. Neither relation grants update or delete. The worker receives only the privileges required for Indexes, chunks, Index Jobs, and search heads; it cannot read accounts, authentication, Sessions, project memberships, receipts, admitted evidence, or cited-answer relations. The Browser has no database role, and every Artifact operation continues through an authenticated API.

## Alternatives considered

**Keep retrieval state in the DSH Host.** The Host would have to duplicate Principal, project authorization, Version, and citation-admission transactions, creating inconsistent permission and audit paths after revocation.

**Let the application role write embeddings.** The query API's database credential would gain index-content mutation privileges, increasing the impact of an input vulnerability or log disclosure.

**Let the worker use the application role.** The worker does not need identity, Session, or project-membership data. A shared role would grant an Artifact-processing process unrelated lateral read access.

**Use an approximate HNSW index for the first retrieval path.** RLS filtering and project scope can affect approximate recall. The first implementation uses exact vector search after RLS to establish a correctness baseline.

**Parse citations from free-form Markdown.** A CommonMark and HTML parser can recover syntax but cannot jointly determine Unicode visual lookalikes, natural Chinese text, and authorization intent. The closed terminal tool makes citation nodes explicit, and the Host grants Artifact capability only to those nodes.

## Testing

- The migrations enable `vector` and `pg_trgm`, create seven retrieval tables, `next_citation_ordinal`, constraints, triggers, RLS, and exact role grants, and support `upgrade → downgrade → upgrade`.
- The database rejects incorrect vector dimensions, duplicate chunk ordinals, body or token overflow, invalid Index-state transitions, a head for a non-ready Index, incorrect receipt TTL, and non-positive citation ordinals.
- RLS exposes only chunks for the current actor's private Artifacts or current project memberships; the worker cannot read accounts, authentication, Sessions, project memberships, or receipts; the application role cannot write chunk embeddings.
- All four retrieval endpoints bound actual streamed body bytes before parsing business requests and reject missing, tampered, expired, replayed, or claim-mismatched delegation tokens. The database stores only nonce digests and necessary ownership fields.
- The Host, FastAPI relay, and internal token-count endpoint impose fixed query, request-body, timeout, and response bounds. The relay accepts only the Host service identity; counting loads only the pinned tokenizer revision and not the embedding inference model.
- Read-only project authorization can reserve unique citation ordinals concurrently without general Session updates. Search output satisfies per-Artifact, total-count, 32 KiB, and 4096-token limits together.
- Session append atomically consumes receipts from a closed and bounded private sidecar, stores project references and public evidence, does not consume a receipt twice on exact idempotent replay, retains the same sidecar for failed retries, and neither rewrites preallocated ordinals nor fills gaps.
- Answers based on admitted evidence publish only through the closed structured terminal tool and reauthorize before success. The first invalid submission permits one correction; the second fails stably, while ordinary conversation, concurrent Sessions, cancellation, and revocation paths disclose no candidate text.
- Admitted evidence and cited-answer provenance are created only by the real append admission path. No-answer batches perform no provenance or history read; cited batches use only bounded citation-ID lookups. The relations survive reload, resume, surface compaction, and a server-derived fork, permit a second currently authorized Project member without an original receipt, and fail closed after membership revocation.
- Retrieval allow and deny audit records contain fixed results and latency, returned evidence contains a bounded identity set, and raw queries, content, vectors, and bearer secrets are excluded.

## Consequences

The deployment's PostgreSQL image must provide the `vector` extension; a database without it fails closed during migration. Deployment must configure the FastAPI Ed25519 public key corresponding to the Host private key, and key rotation cannot leave deployment instances consuming nonces against unshared databases. New worker input or output columns require a simultaneous audit of RLS policies and column and table grants. Future retrieval, indexing, and evidence-admission code must use the persistent state defined here rather than bypass receipts or replace database RLS with application filtering. Citation reopening must use the admitted-evidence and cited-answer relations for historical admission and current-actor RLS for present access; an original receipt or a surface projection cannot substitute for either check.
