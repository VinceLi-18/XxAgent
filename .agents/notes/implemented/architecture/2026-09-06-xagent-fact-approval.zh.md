# Agent Note: 受治理的项目事实审批

Status: implemented

[English](2026-09-06-xagent-fact-approval.md) | 中文

## 问题

项目会话已经能够检索并引用项目证据，但 Agent 尚无持久化通道来提出业务事实并供后续人工审核。若把实时用户审批结果视为这种权限，决定会随重启丢失，审核会与单个轮次耦合，并且 FastAPI 无法以原子方式强制执行项目、证据、修订及审核者之间的关系。

第一个受治理的写入还需要进入源会话历史，但数据库决定不得启动 Agent 轮次。只有匹配的公开工具结果持久准入后，提案结果才能进入可审核状态；重试或并发决定不得重复生成事实修订、审计结果或会话投影。

## 决定

FastAPI 和 PostgreSQL 负责类型化项目事实、不可变提案、精确证据、授权、决定、幂等、审计及交付状态。该实现只治理项目事实这一种对象；在第二种审批对象出现之前不引入通用审批框架。

### 持久审批

拥有项目会话当前访问权限的专家或经理可以提出事实。拥有该项目当前成员身份的经理可以批准或拒绝提案，包括批准自己的提案；提案者可以撤回提案。全局角色本身绝不绕过当前项目成员身份或行级安全策略。

公开生命周期为 `pending -> confirmed | rejected | withdrawn | conflicted`；所有终态均不可逆。批准通过一个可串行化的 FastAPI 事务锁定提案和当前头记录。若基础修订匹配，事务创建下一个正数且不可变的修订、推进同一项目同一字段的头记录、记录决定和审计，并插入一条 Outbox 记录。若头记录已变化，则生成 `conflicted` 状态、审计及 Outbox 记录，但不创建修订。

### 收据绑定的准入

提案准备会创建一条隐藏的 `prepared` 提案，其准入期限为五分钟；随机收据仅以摘要形式存储。FastAPI 将准备结果绑定到已认证主体、源会话及项目、工具调用、权限修订、规范请求载荷哈希和源事件序号。

只有会话追加在同一事务中准入匹配的公开 `tool/result` 和私有收据附件后，提案才变为 `pending`。收据只消费一次，并且绝不进入公开工具结果、会话事件、模型内容、浏览器状态、日志或审计。过期或不匹配的准备结果保持不可见，且不能进入可审核状态。

### 精确证据与不可变事实

提案证据最多引用 64 个已经为源会话准入的不同引用 ID。每条证据记录同时保留持久化准入证据身份和精确的产物文本分片行范围；文件名、URL、对象键及模型提供的产物身份均不具备授权效力。无证据提案必须提供有界且非空的断言理由。

`project_fact_revisions` 存储类型化值，以及在一个项目字段内唯一的正数内容修订。`project_fact_heads` 在每个项目和字段上仅有一行，并使用复合引用，确保头记录不能跨项目或字段指向修订。已确认修订及终态提案的候选字段均不可变。

### Outbox 投影

每个终态提案恰好拥有一条聚合种类为 `fact_proposal` 的不可变 `business_outbox` 记录。事实 UI 直接读取 FastAPI；Outbox 仅用于把决定投影到源会话的持久事件日志。

Host 为源会话拉取有界记录，并追加封闭的 `fact/proposal-decided` 事件。FastAPI 校验 Outbox 身份、提案、会话、载荷哈希和事件身份，随后在准入会话事件的同一事务中把该记录标记为已消费。响应丢失后可以回放而不会新增事件，并且决定事件绝不启动轮次。Fact 插件只从会话日志派生有序的未交付决定，把它们加入下一次用户发起的模型请求；下游流开始后，插件会持久替换临时通知，因此同一轮次的后续步骤、再后续轮次和重启重放都不会重复通知。

### 授权与审计

每个操作都会通过 PostgreSQL 行级安全策略重新检查已认证账户、权限修订、角色、项目成员身份和关联记录。产品读取不显示准备态提案。猜测标识符、成员身份撤销，以及没有项目成员身份的经理均无法获知事实数据。应用角色只获得事实 API 所需的 DML 权限，而 `xagent_worker` 不获得任何事实关系访问权限。

事实审计操作只包含身份、数量、哈希、稳定结果及延迟。按操作感知的数据库校验器会在审计行存储之前拒绝事实内容、理由文本、证据文本、凭据、token、收据、URL 及对象键。

### 浏览器审阅工作台

项目详情栏声明一个可选的 root-scope Fact Slot。只有 Fact UI occupant 存活时才出现第四个页签，因此未组合该包时保留既有三个页签，且不会发出 Fact 调用。仅当已连接、已选择、由服务器授权的 Project Session 处于可见 Fact 页签时，内存控制器才会激活；任何范围或连接变化都会清空状态、取消请求并拒绝迟到结果。

审阅界面使用有界的当前 head 与提案页面、重新授权的详情读取，以及最新优先的不可变修订台账。经理批准或拒绝、提案人撤回仍由服务器授权。每个新决定意图获得一个只在内存中保存的幂等 key；只有传输结果不确定时才显示显式重试，并复用完全相同的请求。证据导航要求每个不可变服务器证据身份都与当前 Session 详情匹配，之后才把 Artifact、Version 和行范围交给 Artifact opener。`propose_fact` ToolView 只渲染封闭的公开结果 metadata，绝不读取参数、结果正文、收据、URL 或模型创作的证据字段。

## 考虑过的替代方案

**使用实时 DSH 用户审批能力。** 该决定只授权实时轮次中的一次操作，无法表示异步审核、PostgreSQL 授权、不可变业务历史或重启恢复。该能力保持不变，也不授权事实提案。

**构建通用的多对象审批框架。** 目前只有一种受治理对象具备已确认的语义。通用聚合层会固化未经验证的抽象，因此首个 schema 只接受 `fact_proposal`；第二种对象确定共享要求后再进行泛化。

**准备时直接把提案写为 pending。** 这样，失败或取消的会话追加可能遗留数据库行，却没有权威工具结果。收据绑定的准入使产品可见性与持久会话记录保持一致。

**批准时直接追加决定。** FastAPI 不能依赖实时 Host，也不能启动 Agent 轮次。单聚合 Outbox 使数据库决定保持原子性，同时让会话交付可回放并可独立恢复。

**信任模型提供的引用或分片字段。** 这些字段可能指向不可访问或不匹配的证据。指向准入证据及精确不可变分片范围的复合引用让数据库强制执行获授权身份。

## 验证

- 七个事实关系强制执行封闭的值、生命周期、聚合、操作、字段键、修订、身份和唯一性规则，包括同一项目同一字段的头记录引用及精确的准入证据范围。
- 数据库触发器拒绝修改已确认修订、终态提案和决定 Outbox 记录，也拒绝无效的头记录推进；事实关系或事实审计行非空时，迁移会在执行任何 schema 变更之前拒绝降级。
- 行级安全策略仅允许当前项目成员执行其获准操作，对产品读取隐藏准备态提案，并拒绝工作进程角色访问所有事实关系。
- 提案准入只消费匹配、未过期且以摘要形式存储的收据；批准或冲突以原子方式写入提案、适用时的修订、头记录、审计、幂等记录及一条 Outbox 记录。
- Outbox 交付在会话追加时有界且只发生一次，不创建 Agent 轮次，也不暴露收据、token、证据文本、URL 或对象键。

## 后果

复合引用和变更触发器使首个迁移有意保持严格；应用事务必须按规定顺序获取记录，且不能通过兼容回退修复不一致数据。只有七个事实关系和事实审计流均为空时才允许降级，因此已部署业务数据的回滚需要经过审核的备份。

单对象 Outbox 和事实专用幂等存储重复了一些以后受治理对象也可能需要的结构。泛化将推迟到另一种审批对象提供具体共享语义之后；后续迁移必须保留现有事实身份和授权保证。
