# XAgent Phase 7B 产物详情投影设计

[English](2026-09-13-xagent-phase-7b-artifact-design.md) | 中文

## 范围与交付

Phase 7B 将产物详情摘要推导迁入现有 TypeScript 后端客户端，涵盖详情查询、上传完成、扫描重试及其持久化幂等快照转换。公开浏览器 Remote 方法、结果类型和可视行为保持不变。本文是一个迁移批次的参考规格，不授权执行生产迁移。

实施前检查 Phase 7A 的集成结果，从最新 main 开始。Phase 7B 独立发布，不将其实现加入 Phase 7A 的 PR（Pull Request）。分配下一迁移版本前确认当前 Alembic head，禁止改写历史迁移。

## 职责与排除项

FastAPI 负责认证、当前读写授权、RLS、上下文规范化、扫描状态、安全版本字段披露、事务、审计、请求哈希、幂等和后台任务。TypeScript 接收已授权数据并推导浏览器详情摘要。不引入数据库凭据、新 Cordis 服务、授权缓存或额外 HTTP 请求。

产物列表响应保留现有 SQL/Python 职责和摘要格式，不得仅为转移计算而携带完整版本历史。下载 URL、扫描、Docling、OCR、Office 处理、embedding、Fact 审批、Outbox 事件、Session 格式及 UI 设计均不属于本批次。

## 内部协议与投影

三个返回详情的端点均要求请求体包含 `schema_version: 2`，返回的详情对象仅包含 `schema_version: 2`、`id`、`display_name`、`scope`、`can_edit` 和 `versions`。操作原有的专属请求字段仍为必填。详情路由使用独立请求模型，列表路由保留空请求。缺失或不支持的请求版本必须在写入或幂等回放前以 HTTP 422 拒绝。Host 按现有 schema 错误映射拒绝缺失、旧版或未知响应版本。

版本项保留现有字段名、可选字段省略规则及校验。私有作用域仅包含类型；项目作用域另含其已授权项目 ID。FastAPI 不得泄露所有者 ID、对象键、暂存凭据或不允许披露的哈希。哈希继续仅按现有 clean/quarantined 规则披露。

Host 发布前校验完整详情：版本列表非空且有界，版本 ID 和版本号唯一，正整数版本号严格降序，状态有效，并满足现有大小、哈希及作用域约束。不静默排序、去重、丢弃无效项或发布部分结果。最新版本及状态取自首项，最新 clean 版本取自首个 clean 项；不存在时省略公开结果中的可选 clean 版本字段。最新版本为 pending、scanning、failed 或 quarantined 时，不隐藏较旧的 clean 版本。

## 持久化快照与请求身份

上传完成和扫描重试将同一版本 2 详情保存到 `result.detail`。回放在现有当前授权检查后返回已存详情，而非重新查询详情。worker 进度和后续版本不得改变回放快照。

操作名保持 `artifact.upload.complete` 和 `artifact.version.retry`。保留 actor ID、幂等键、请求哈希、外层结果 ID、时间戳和过期时间。传输协议版本不参与业务请求哈希，添加该字段不得使迁移后的有效重试发生冲突。禁止更换操作名以避开旧键、清空记录、延长有效期或产生重复写入。

已存快照属于持久化输入，返回前必须显式校验格式。不支持或损坏的详情以稳定的服务不可用响应失败，不产生新写入或静默回退。运行时代码仅支持版本 2，历史格式转换仅由迁移负责。

## 数据迁移与逆向转换

新增一个事务性 Alembic 数据迁移，仅处理 `xagent_idempotency_keys` 中操作为上传完成或扫描重试的行，包括已过期行。其他操作及所有其他列保持不变。使用已配置的迁移角色，不扩大应用授权，也不在运行时代码中禁用 RLS。

升级按实际输出的旧格式校验每个详情，并验证摘要与其已存版本一致。随后移除 `latest_version`、`latest_status` 和 `latest_clean_version`，添加 `schema_version: 2`。所有保留的 JSON 值及可选字段省略状态不变。迁移仅读取各自的已存快照，不读取产物或版本的实时状态、外部存储或 worker。

逆向转换先校验版本 2，再从其已存版本重建三个旧摘要字段，移除协议版本；不存在 clean 版本时省略对应字段。该转换同时适用于升级转换的记录和版本 2 新写入的记录。支持的旧快照必须往返后 JSON 相等，包括嵌套值及省略语义；JSONB 键顺序不影响判断。

任一目标记录无效时，整个事务中止，Alembic 版本保持不变。禁止猜测修复、跳过过期记录、记录快照内容或独立提交分批结果。迁移诊断指出操作及违反的字段规则，不泄露令牌、对象键、文件名或快照内容。迁移实现自包含，不导入可变的应用投影辅助函数。

## 部署与回滚

使用维护窗口：停止接收两个受影响写操作并排空在途请求，停止旧 Host/API 实例，按部署环境的受保护备份流程备份受影响数据，然后执行数据升级。部署配套的版本 2 Host/API，执行带认证的查询、完成、重试及回放冒烟测试，再恢复流量。不支持混合版本滚动部署；排空、备份、迁移或冒烟测试失败时中止。

回滚也要求停止接收请求并排空写入。使用新版本的迁移工具逆向转换本数据迁移，再启动配套的旧 Host/API。按已存预期响应验证回放后恢复流量。仅恢复旧二进制文件不足以回滚。两个方向均不改变不可变的产物版本、处理任务、请求身份或授权策略。

## 验证与验收

- Host 测试比较查询、完成和重试的公开详情不变，覆盖旧 clean/新 pending、无 clean、隔离及失败状态；拒绝空列表、重复、乱序、超限、损坏和不支持版本的响应。
- API 测试固定三个端点的精确版本 2 字段，并在任何版本、任务或幂等数据变更前拒绝旧版及缺失版本的请求。列表、预览、下载、上传初始化及敏感字段披露保持不变。
- PostgreSQL 迁移测试覆盖两类操作、多个 actor、过期记录、无关操作、哈希及过期时间和外层 ID 保留、精确升级/逆向往返、新版本 2 记录的回滚转换，以及无效记录触发的全有或全无失败。
- 回放测试跨越真实迁移和进程重启，推进 worker 状态后重试原请求。公开结果仍与首次响应相等，副作用数量不增加，当前撤权仍拒绝访问。包含同键并发重试和不同输入冲突。
- 真实产物 Loader 场景覆盖公开 Remote 路径；Docker 产物流水线覆盖上传、扫描、重试与读取集成。不计划改变模型输出或 GUI；若实现改变任一项，同一变更中须补充要求的快照或录制 GUI 验收。
- 文档在受影响 README 和既有产物 Agent Note 中说明协议职责、迁移前提、回放不变量及包含数据转换的回滚。运行聚焦包/API 测试、迁移检查、build、lint、doc-sync（文档同步门禁）及差异检查；区分计划检查与已执行证据。

## 实施顺序

1. 补充失败的协议、投影和持久化回放回归测试，明确预期公开响应。
2. 同步实现 Python 版本 2 详情与 Host 投影，保留授权及业务请求身份。
3. 添加自包含数据迁移与逆向转换，在 PostgreSQL 上证明事务失败和 JSON 往返行为。
4. 补全调用方 fixture（测试前置数据）与组装验收，更新所属文档，在一次性数据上演练部署与回滚。

实施计划必须基于选定 main 版本明确测试命令、文件、迁移父版本及预期失败。本文不声明迁移或相关测试已实现。
