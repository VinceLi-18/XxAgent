# XAgent Phase 3A 项目工作台验证记录

本记录覆盖 XAgent Business 的账号级项目工作台、项目创建权限、三栏项目上下文、跨项目统计入口、Session 项目引用和账号切换隔离。实现只发生在 XxAgent；JiaxinAgent 来源仓库和普通 DSH Profile 没有修改。

## 已交付边界

- 工作台 Bootstrap 由 FastAPI 按当前认证账号返回账号摘要、能力、当前上下文、可访问项目、Session 范围和统计摘要。浏览器不自行拼装授权结果，也不把本地缓存当作权限真源。
- Manager 默认拥有 `project.create`；Specialist 只有得到服务器授权后才拥有该能力。项目创建在授权事务内完成；能力授予和撤销会推进账号权限版本，使旧登录态随版本变化失效。
- 「我的工作台」是跨项目业务入口，汇总当前账号可访问项目与私有 Session，不要求用户创建额外的统计对话。项目上下文只显示服务器授权映射到该项目的 Session。
- 左栏提供工作台、项目列表、项目创建和当前范围 Session；中央栏保留对话；第三栏显示当前工作台或项目详情。登录成功、创建项目和切换上下文会打开第三栏；窄屏按共享布局规则让步为可开关的模态抽屉。
- 浏览器状态以账号为缓存分区。退出并切换账号时会取消旧请求、清空 Session 与项目状态，再从服务器装载新账号工作台；迟到响应不能覆盖新账号。
- Session list、open、resume、fork、send、subscribe 与事件读取都以服务器授权的 Session 引用为入口。项目引用复制通过受限数据库函数完成，不把 actor 或项目身份交给 RPC payload 决定。
- `xagent-developer`、普通 `web`、`headless` 和其他上游 Profile 不装载 XAgent 项目工作台、账号能力或项目引用运行时，继续保持原有行为。

## 真实多账号与 UI 验证

构建版 FastAPI 使用独立 PostgreSQL 数据库，构建版 CLI 以全新 `DSH_HOME` 和 `DSH_AGENTS_HOME` 启动 `xagent-business`。同一浏览器流程先登录 Manager，创建真实项目「北极星项目」，验证项目三栏详情与跨项目工作台统计；随后在 900px 真实窄屏打开并关闭上下文栏抽屉，再退出登录并切换到 Specialist。Specialist 页面没有 Manager 的项目，也没有「新建项目」入口，证明项目缓存与创建能力随账号重新从服务器装载。

GIF 位于忽略目录 `.playwright-mcp/xagent-phase3a-project-workbench.gif`，未提交或发布。它由同一次连续运行的 6 张真实源帧编码为 107 帧、1200×750、10 fps、10.7 秒、470,671 字节，SHA-256 为 `2c632c21255d69185b85bcd6ca9d35723c7389db4359f0d74e59da9dc5a32059`。宽屏源帧使用 1440×900 视口；窄屏源帧使用 900×900 视口并只在右侧补入同色空白，使所有编码源统一为 1440×900，没有拉伸或模拟窄屏布局。源帧、GIF 和六个代表帧均经过视觉检查，未包含密码明文、Cookie、令牌、服务身份或数据库内容。

测试环境没有 `DEEPSEEK_API_KEY`，因此没有伪造模型回合。该限制不影响本阶段的账号、项目、Session 引用、三栏布局和缓存隔离验收。
