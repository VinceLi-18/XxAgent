# @xagent/dsh-fact

[English](README.md) | 中文

`@xagent/dsh-fact` 为 XAgent Business 项目会话提供受治理的 Fact 服务。它把模型提出的 Fact 准备为稍后的人工作审，提供已认证的浏览器读取和决策 Remote，并把持久决策事件追加到来源会话。

服务只从物理认证请求上下文接受提案权限。带作用域的 `propose_fact` 执行进入消费方前会刷新该 Agent 的会话，使精确 `tool/call` 身份先持久化；取消或刷新失败会阻止提案请求。服务为当前身份、权限修订、固定项目、会话、工具和工具调用签发精确且短时有效的委托凭证。浏览器 Remote 同样从连接上下文派生用户令牌和固定项目；调用方不能提交身份或所有权字段。

提案收据与 Outbox 身份保存在两个独立私有注册表中。会话持久化按事件序列范围读取它们的附件，并且只在 FastAPI 确认对应追加后提交。会话打开和 `agent/pre-step` 通过每个会话唯一的所有者拉取最多 32 条 Outbox 记录，追加普通 `fact/proposal-decided` 事件，且绝不启动轮次。会话存在尚未投影的决定或仍在表面的决定通知时不会拉取下一页；当前页持久消费后才允许拉取下一页。每个已认领收件箱批次的物理作用域授权其完整模型步骤；错误只释放活跃所有权，并保留稍后排队消息的绑定。

## 模型体验

### 受治理的 Fact 生命周期

#### 模型看到什么

提供方本身不增加常驻提示词或工具模式。仅限项目会话的消费方只返回提案 ID 与 `pending` 状态。Outbox 交付把 `fact/proposal-decided` 追加为只进入日志、不进入表面的会话事件。在下一个由用户发起轮次的第一个模型步骤中，插件按事件顺序投影当前页中最多 32 条未交付决定，并在下游迭代器产生第一个结果后持久替换临时通知。同一轮次的后续步骤、再后续轮次和重放都不会重复通知。收据、令牌和证据内容从不进入投影。

#### Token 影响

Outbox 交付本身不增加模型令牌。下一个由用户发起的请求携带一条只含事件公开字段的有界通知；消费该通知后，后续请求投影不再包含它。

#### KV Cache 影响

Outbox 交付只追加会话历史，不调度模型请求，因此不会使正在使用的 KV 缓存失效或增长。下一个由用户发起的请求会在请求前缀中加入一次决策通知；持久替换确保后续请求前缀不再包含该通知。

## 已知限制与延期工作

- 本包不注册 `propose_fact` 模型工具或其渲染器；它们属于独立的 Business Profile 插件。
- 每次会话打开或 pre-step 触发只读取一页 Outbox；其余记录等待后续触发。
- 私有和匿名会话不能准备、读取或决定受治理的 Fact。
